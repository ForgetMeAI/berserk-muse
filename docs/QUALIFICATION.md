# Проверки и ограничения Berserk

Актуальный статус на **2026-10-23**. Полный локальный набор прошёл **556/556** теста на macOS с Node **22.23.3** и **26.0.0**. Оба запуска завершились успешно, без пропусков и отмен; хеши исходников до и после совпали. [Манифест проверки](verification-2026-10-23.json). Результат проверяет текущие тесты и fixtures; он сам по себе не подтверждает генерацию через живой Muse. Результаты CI для текущих коммитов публикуются в [GitHub Actions](https://github.com/ForgetMeAI/berserk-muse/actions).

Первый CI-прогон выявил две нестабильные проверки на Node 22: таймер cooldown и позднее тело OTP-ответа. Проверки переведены на управляемое время и явные события; производственный код для этого не менялся. После исправления локально повторно прошли 556/556 тестов на обеих версиях Node.

## Vendor-assets

Закреплённый старый lock от 18 октября содержал 213 публичных URL. При проверке 23 октября **42** ещё отвечали HTTP 200, а **171** возвращал HTTP 404. Поэтому один только hash-lock с неизменными адресами не обеспечивал запуск на новой установке.

Текущий набор содержит **108** проверенных публичных assets и предоставляет четыре нужных функции по именам семантических экспортов, без жёсткой привязки к номерам модулей. `npm run test:vendor` прошёл на Node 22.23.3 и 26.0.0. Отдельно проверен реальный resolver: старый набор из 213 адресов обновился до 108, было скачано 108 публичных файлов, после перезапуска скачиваний не было и проверенная генерация кэша использовалась повторно.

Перед первой генерацией и затем не чаще одного раза в десять минут resolver сравнивает текущие публичные script URL с выбранным lock. При смене URL сборки, а также при ответах 404/410, он ограниченно обнаруживает необходимые assets и зависимости. Каждая загрузка сверяется с SHA-256 allowlist; кэш и lock выбираются атомарно после проверки семантических контрактов. Обхода проверки хешей нет. HTML сессии используется в памяти, но не записывается в vendor-кэш.

## Живые проверки на 2026-10-23

На трёх новых принадлежащих владельцу тестовых аккаунтах Luuvan подтверждены доставка свежего OTP и его автоматический ввод в Muse. Сохранение сессии и завершённая генерация пока **не подтверждены**. В завершающем прогоне с автоматическим окном 60 секунд вход корректно завершился `muse_vm_unavailable`, без перехода в дополнительное ручное ожидание. Производственный срок автоматического входа — 180 секунд.

У двух ранее заведённых тестовых сессий Muse `/api/session` возвращал HTTP 200 с `status: unavailable`; разрешение VM завершилось retryable-состоянием `vm_resolution_issue.kind`. В принадлежащем владельцу браузерном профиле новая изолированная беседа Muse показала страницу ошибки. Эти наблюдения не доказывают, что текущая генерация работает или что ошибка устранена. Свежий баланс нового аккаунта также не проверялся.

Браузерный transport теперь ждёт готовности гидратированного поля, подтверждает создание новой беседы и ждёт подтверждение именно отправленного пользовательского сообщения. Восстановление ошибочных escape-последовательностей ограничено обычным полем `content`; JSON аргументов инструментов остаётся строгим. Эти проверки и unit-тесты не заменяют успешную live coding-задачу на текущем коде.

Пошаговые сообщения об ошибках vendor assets и недоступной VM собраны в [руководстве по диагностике](TROUBLESHOOTING.md).

- **2026-10-21:** 512/512 тестов прошли на macOS с Node 22.23.3 и 26.0.0. [Манифест](verification-2026-10-21.json) относится к тогдашнему набору и не описывает текущую ревизию.
- На Luuvan и Generator.email тогда были подтверждены получение кода, автоматический ввод и сохранение сессии; для одного Generator-аккаунта также проверялись health-check, баланс и восстановление после перезапуска. Это история прежних проверок, а не подтверждение текущего состояния или нового аккаунта. На отдельном почтовом ящике свежие сообщения не наблюдались при Muse HTTP 201; причина не установлена.
- Claude Code 2.1.303, Hermes 0.16.0 и OpenCode проходили прежние изолированные coding-gates через Muse. Они относятся к зафиксированным тогда исходникам и не повторялись для текущих байтов. Полный финальный аудит Claude Opus для текущей ревизии не выполнен.
- На Debian Linux x64 с Node 22.23.3 ранее прошли 416/416 тестов и запуск, health-check, панель пустого сервиса и остановка. Поздние изменения на Linux отдельно не проверялись. **WSL2 не проходил реальную квалификацию.**

## Практические границы

Проект экспериментальный и не является официальным Muse API. Баланс читается из подписи Muse; сокращённые K/M/B значения приблизительны. Локальный usage — оценка текста, а не биллинг. Наблюдения о балансе из исторических проверок не переносятся на новые аккаунты.

Сохранённые сессии и почтовые ссылки предназначены только для локального каталога `.state` и не входят в репозиторий. CAPTCHA, Terms и запросы разрешений остаются пользователю. Gmail/Outlook требуют отдельного scoped OAuth либо ручного входа.
