# Проверки и ограничения Berserk

Актуальный статус на **2026-10-25**: реальные coding-задачи через Muse подтверждены для Claude Code **2.1.303** и Hermes **0.16.0** на macOS arm64 с Node **26.0.0**. Проверен код коммита [`9375856`](https://github.com/ForgetMeAI/berserk-muse/commit/9375856f25d4210b1c1e9c17fa7a50e4602d586d); все **112** файлов исходников, скриптов, тестов и package-файлов совпали с запущенной копией. Для публикации результатов производственный код не менялся. [Обезличенный отчёт](verification-2026-10-25.json).

Полный локальный набор **23 октября** прошёл **556/556** тестов на macOS с Node **22.23.3** и **26.0.0**, без пропусков и отмен; хеши исходников до и после совпали. [Манифест unit-проверки](verification-2026-10-23.json). Он сам по себе не подтверждает генерацию через живой Muse. Результаты CI для каждого опубликованного коммита доступны в [GitHub Actions](https://github.com/ForgetMeAI/berserk-muse/actions).

Первый CI-прогон выявил две нестабильные проверки на Node 22: таймер cooldown и позднее тело OTP-ответа. Проверки переведены на управляемое время и явные события; производственный код для этого не менялся. После исправления локально повторно прошли 556/556 тестов на обеих версиях Node.

## Vendor-assets

Закреплённый старый lock от 18 октября содержал 213 публичных URL. При проверке 23 октября **42** ещё отвечали HTTP 200, а **171** возвращал HTTP 404. Поэтому один только hash-lock с неизменными адресами не обеспечивал запуск на новой установке.

Текущий набор содержит **108** проверенных публичных assets и предоставляет четыре нужных функции по именам семантических экспортов, без жёсткой привязки к номерам модулей. `npm run test:vendor` прошёл на Node 22.23.3 и 26.0.0. Отдельно проверен реальный resolver: старый набор из 213 адресов обновился до 108, было скачано 108 публичных файлов, после перезапуска скачиваний не было и проверенная генерация кэша использовалась повторно.

Перед первой генерацией и затем не чаще одного раза в десять минут resolver сравнивает текущие публичные script URL с выбранным lock. При смене URL сборки, а также при ответах 404/410, он ограниченно обнаруживает необходимые assets и зависимости. Каждая загрузка сверяется с SHA-256 allowlist; кэш и lock выбираются атомарно после проверки семантических контрактов. Обхода проверки хешей нет. HTML сессии используется в памяти, но не записывается в vendor-кэш.

## Живые coding-проверки на 2026-10-25

Оба клиента последовательно работали через HTTP-транспорт Berserk с одним доступным принадлежащим владельцу тестовым аккаунтом и моделью `muse-web`. Это Claude Code и Hermes как клиенты модели Muse; проверка не означает использование модели Claude Opus.

Задача — исправить ошибку расчёта процентного налога в `invoice.mjs`. Каждый клиент сначала воспроизвёл падающие тесты, прочитал исходник, исправил формулу, получил **3/3** проходящих теста, создал и прочитал `proof.json`, затем дал итоговый ответ. Тестовый файл не менялся; отдельный verifier без сети подтвердил расчёты для обычной, дробной и нулевой ставки. Клиенты могли менять только два файла задачи и свой временный профиль; OS sandbox подтвердил запрет внешней сети, чтения личных файлов и записи за пределами разрешённых путей.

| Клиент | Результат | Запросы к Muse | Выполненные действия |
| --- | --- | --- | --- |
| Claude Code 2.1.303 | `PASS_EXPERIMENTAL_LIVE_CLIENT` | 7 завершены, 0 ошибок | 6 вызовов Bash, все этапы и итоговый ответ проверены автоматически |
| Hermes 0.16.0 | `PASS_EXPERIMENTAL_LIVE_CLIENT_REVIEWED` | 6 завершены, 0 ошибок | 5 вызовов terminal; совместная запись/чтение подтверждения проверена отдельно |

У Hermes автоматический runner сохранил `FAILED_EXPERIMENTAL_LIVE_CLIENT`: запись и чтение подтверждения произошли одной командой, а автоматический ledger требует отдельного вызова чтения. Независимая проверка записей только одноразовой тестовой сессии сопоставила точные хеши команды и результата с live-отчётом. Подтверждён прямой `fs.writeFileSync` с последующим `console.log(fs.readFileSync(...))`, успешное выполнение и совпадение JSON вывода с файлом на диске. Исходный автоматический результат сохранён; отдельная квалификация с ревью не меняет правил runner и не требует повторных запросов к Muse.

Первые попытки **не были успешными**: Claude Code 2.1.169 выполнил все действия и прошёл тесты, но последний запрос завершился `no_ready_account` до отправки; у Hermes 0.16.0 после пяти действий ответ был отклонён как `invalid_model_response`. Ещё один запуск Hermes остановился на sandbox-preflight до запросов модели; повторная подготовка с `TMPDIR=/private/tmp` прошла. Приведённые в таблице результаты относятся к новым отдельным задачам, без автоматической переотправки прежних запросов. Причина отдельных сетевых/форматных отказов полностью не установлена; устойчивость длительных сессий этим прогоном не доказана.

В тот же день Muse назначил VM, обычная генерация непосредственно на сайте прошла, новый тестовый аккаунт завершил вход с сохранением сессии, а локальный API успешно вернул текст и отдельно выбрал предложенный инструмент. Флаг `isGeoGated` оставался `true` при работающей генерации: один этот флаг не доказывает геоблокировку. Смена VPN совпала с восстановлением доступности, но причинная связь не установлена. Один прежний аккаунт после двух `invalid_model_response` временно исключён из локальной ротации; его сессия сохранена.

### Повторение на macOS

Нужны запущенный локальный Berserk без других запросов, доступный собственный аккаунт и отдельно установленные клиенты. Используйте абсолютный путь к исполняемому файлу; проверенные версии указаны в таблице.

```sh
node scripts/verify-claude-live.mjs --claude-bin /absolute/path/to/claude
TMPDIR=/private/tmp node scripts/verify-hermes-live.mjs --hermes-bin /absolute/path/to/hermes --approve-isolated-hermes
```

Вторая команда разрешает подтверждения только в одноразовом процессе Hermes внутри OS sandbox. Основные настройки клиентов не меняются. Runner сохраняет отчёт локально; автоматический FAIL нельзя считать PASS без разбора доказательств. Совместная запись/чтение может потребовать описанной выше отдельной проверки. Полные отчёты и временные профили в GitHub не публикуются.

## Предыдущие живые проверки: 2026-10-23

На трёх новых принадлежащих владельцу тестовых аккаунтах Luuvan были подтверждены доставка свежего OTP и его автоматический ввод в Muse. На том этапе сохранение сессии и завершённая генерация **не были подтверждены**. В завершающем прогоне с автоматическим окном 60 секунд вход корректно завершился `muse_vm_unavailable`, без перехода в дополнительное ручное ожидание. Производственный срок автоматического входа — 180 секунд.

У двух ранее заведённых тестовых сессий Muse `/api/session` возвращал HTTP 200 с `status: unavailable`; разрешение VM завершилось retryable-состоянием `vm_resolution_issue.kind`. В принадлежащем владельцу браузерном профиле новая изолированная беседа Muse показала страницу ошибки. Это наблюдения от 23 октября, до успешных генераций 25 октября. Свежий баланс нового аккаунта также не проверялся.

Браузерный transport теперь ждёт готовности гидратированного поля, подтверждает создание новой беседы и ждёт подтверждение именно отправленного пользовательского сообщения. Восстановление ошибочных escape-последовательностей ограничено обычным полем `content`; JSON аргументов инструментов остаётся строгим. Эти проверки и unit-тесты не заменяют успешную live coding-задачу на текущем коде.

Пошаговые сообщения об ошибках vendor assets и недоступной VM собраны в [руководстве по диагностике](TROUBLESHOOTING.md).

## Практические границы

Проект экспериментальный и не является официальным Muse API. Баланс читается из подписи Muse; сокращённые K/M/B значения приблизительны. Локальный usage — оценка текста, а не биллинг. Наблюдения о балансе из исторических проверок не переносятся на новые аккаунты.

Свежая coding-проверка ограничена синтетической задачей, одним доступным аккаунтом и macOS. Она не квалифицирует длительную работу, массовую ротацию, свежий баланс, перезапуск/восстановление, native tool calling Muse, Linux/WSL2 или будущие изменения сайта и кода.

Сохранённые сессии и почтовые ссылки предназначены только для локального каталога `.state` и не входят в репозиторий. CAPTCHA, Terms и запросы разрешений остаются пользователю. Gmail/Outlook требуют отдельного scoped OAuth либо ручного входа.
