# Руководство Berserk

## Содержание

Berserk — экспериментальный локальный мост кодинг-клиентов к приложению Muse, а не официальный API Meta. Есть OpenAI Chat Completions и Anthropic Messages для Claude Code; статус реальных проверок указан ниже. Основной режим использует сохранённые сессии аккаунтов и прямой HTTPS/WebSocket-транспорт. Каждый WebSocket работает в отдельном локальном процессе Node; закрытие подтверждается только после выхода этого процесса. Браузер нужен при входе в аккаунт; во время генерации окно Muse не требуется.

## Запуск

Требуются Node.js 22 или новее и установленный Chrome/Chromium для первого входа. Для Windows выполняйте команды внутри WSL2; подробности — в разделе платформ ниже.

```sh
git clone https://github.com/ForgetMeAI/berserk-muse.git
cd berserk-muse
npm ci --ignore-scripts
npm run launch                 # HTTPS + native WebSocket по умолчанию
npm run panel                  # открыть локальную панель без входа
```

В панели нажмите **«Добавить аккаунты»**, вставьте строки `почта | ссылка на почту` и дождитесь статуса **«Активен»**. Если автоматический вход недоступен, завершите его в открывшемся окне Muse. Поддерживаемые почтовые сервисы и массовый импорт описаны ниже.

После подключения аккаунта запустите нужный установленный клиент:

```sh
npm run client -- claude --work-dir ./workspace
# или
npm run client -- hermes --work-dir ./workspace
```

Клиенты устанавливаются отдельно. Старый OpenCode-лаунчер `npm run agent -- "Опиши задачу"` предназначен для macOS. Проверить сервис можно командой `npm run status`, остановить — `npm run stop`.

HTTP-режим нужно считать экспериментом до прохождения перечисленных ниже end-to-end gates. Сервис слушает loopback; порт задаёт `MUSE_PORT` (по умолчанию `8787`). В HTTP-режиме допускается до `MUSE_MAX_ACTIVE` активных логических запросов (по умолчанию 1) и `MUSE_QUEUE_LIMIT` ожидающих запросов (по умолчанию 4; максимум 100). Соединение до отправки генерации может быть восстановлено один раз через существующий лимит refresh. Повторная отправка разрешена только если транспорт доказал, что запрос ещё не был принят; принятый или неоднозначный запрос автоматически не воспроизводится. Возврат к прежнему транспорту задаётся явно через MUSE_TRANSPORT=browser после остановки сервиса.

## Модель и локальный API

Адрес подключения — `http://127.0.0.1:8787/v1`, локальный API key — `muse-local`, модель — `muse-web` (также поддерживается alias `muse`). OpenCode уже настроен на этот провайдер. Alias не переключает модель внутри Muse.

Сохранены `POST /v1/chat/completions`, каталог моделей и health endpoints. Добавлены `POST /v1/messages` и локальный `POST /v1/messages/count_tokens`. Инструменты передаются как проверяемый JSON и выполняются выбранным клиентом; SSE буферизуется до окончания ответа. Лимит контекста задаётся `MUSE_MAX_CONTEXT_CHARS`; оценки `usage` и `X-Muse-Usage` не являются балансом или биллингом Meta. Text-only Messages поддерживает `tool_use`/`tool_result`; изображения, документы и server tools отклоняются. Extended thinking, output constraints и stop sequences не имитируются, ограничения помечаются заголовком `X-Muse-Unsupported-Options`.

## Claude Code и Hermes

Установите нужный клиент отдельно. Запуск с отдельным профилем и моделью Muse:

```sh
npm run client -- claude --work-dir ./workspace
npm run client -- hermes --work-dir ./workspace
# Необязательные параметры: --port 8787, --executable /absolute/path/to/client
# После -- можно передать дополнительные аргументы самому клиенту.
```

Лаунчер ищет клиент в PATH, создаёт отдельный профиль внутри `.berserk-client-profiles` рабочей папки и передаёт только разрешённые переменные окружения. Пользовательские настройки и ключи основного профиля не переносятся. Запускается интерфейс выбранного клиента с Muse, а не модель Claude. Применяются обычные запросы разрешений самого клиента; это не тот же OS sandbox, что у macOS-лаунчера OpenCode и проверочного runner. Не добавляйте каталоги профилей в Git.

Hermes, установленный из исходников, может дополнительно читать `.env` своего checkout даже с отдельным `HERMES_HOME`. Лаунчер проверяет известный вариант такой установки и отказывает при наличии этого файла, не открывая его. Используйте чистую установку; основной профиль не удаляется и не изменяется. Произвольные сторонние wrapper-скрипты отдельно не проверены.

Claude Code использует `ANTHROPIC_BASE_URL=http://127.0.0.1:8787` **без `/v1`**, локальный bearer `muse-local` и `ANTHROPIC_MODEL=muse-web`. Hermes использует custom provider, `api_mode: chat_completions`, адрес `http://127.0.0.1:8787/v1` и тот же локальный ключ. Для Hermes основной и вспомогательные model-запросы направляются в Berserk; внешние model-fallback не настраиваются. Примеры: [Claude environment](../examples/claude-code.env.example), [Hermes config](../examples/hermes.config.yaml). Не заменяйте ими основной пользовательский профиль без собственного решения.

Проверенная 25 октября версия Claude Code — **2.1.303**: полный изолированный coding-прогон через Muse завершился успешно. Сверяйте `claude --version`; отдельный бинарник можно выбрать через `--executable`. Сам лаунчер клиент не обновляет. `CLAUDE_CODE_SIMPLE=1` и отдельный `CLAUDE_CODE_TMPDIR` входят в проверенную конфигурацию. Лаунчер также задаёт `CLAUDE_CODE_MAX_RETRIES=0`, поддерживаемую переменную Claude Code, чтобы CLI не повторял сбойный или неоднозначный запрос к Muse ([официальная документация](https://code.claude.com/docs/ko/env-vars)).

Проверенная версия Hermes — **0.16.0** (дата релиза в выводе CLI — `2026.6.5`, это не версия пакета). Для custom Chat Completions задаются одна внешняя попытка (`agent.api_max_retries: 1`) и `HERMES_STREAM_RETRIES=0`; у этой версии Hermes SDK retries отключены в клиенте, создаваемом для каждого Chat Completions-запроса.

Временные файлы клиентов и оболочки направляются в отдельный профиль: `TMPDIR`, `CLAUDE_CODE_TMPDIR` и zsh `TMPPREFIX`. Это позволяет выполнять here-document внутри ограниченной папки; `TMPDIR` сам по себе не меняет стандартный путь временных файлов zsh ([документация](https://zsh.sourceforge.io/Doc/Release/Parameters.html#index-TMPPREFIX)).

Официальные настройки клиентов: [Claude Code gateways](https://code.claude.com/docs/en/llm-gateway), [Hermes providers](https://hermes-agent.nousresearch.com/docs/integrations/providers). Текущий статус тестов и live-проверок описан в [квалификации](QUALIFICATION.md), а типовые ошибки — в [руководстве по диагностике](TROUBLESHOOTING.md). Ответ на обычное сообщение сам по себе не доказывает работу кодинг-инструментов.

## Linux и Windows через WSL2

Подготовлены macOS и Linux; для Windows выбран **WSL2**, нативный Windows-процесс сервера явно отклоняется. На Windows установите Ubuntu по [официальной инструкции Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install), затем выполняйте команды проекта в Linux-терминале WSL. Проект и `.state` храните в Linux home, например `~/berserk`, а не на `/mnt/c`: хранилище требует POSIX-прав `0600/0700`. Node.js 22+ и клиенты также устанавливаются внутри Linux/WSL.

Для первоначального логина нужен установленный Linux Chrome/Chromium и графический сеанс (на WSL — WSLg). `playwright-core` браузер не скачивает. Можно явно указать его путь:

```sh
MUSE_BROWSER_EXECUTABLE=/usr/bin/chromium npm run launch
npm run panel
```

Linux-лаунчер панели использует `xdg-open`; если открыть браузер не получилось, напечатанный `http://127.0.0.1:8787/panel` можно открыть вручную. [Windows обычно получает доступ к Linux localhost-сервису](https://learn.microsoft.com/en-us/windows/wsl/networking). Локальный Host/Origin и привязка к loopback сохраняются; порт наружу не публикуется. Старый `npm run agent` с `sandbox-exec` относится к macOS; для новых клиентов используйте `npm run client`.

На Debian Linux x64 с Node 22.23.3 прошли **416/416** тестов и запуск → status → health → панель с пустым списком аккаунтов → остановка. Этот исторический прогон использовал отдельную временную папку; вход в Muse, генерация и графический браузер на Linux не проверялись. Фактический прогон внутри WSL2 ещё не выполнен. Текущий CI проверяет Ubuntu/macOS × Node 22/26; результаты каждого коммита доступны в [GitHub Actions](https://github.com/ForgetMeAI/berserk-muse/actions).

## Аккаунты и панель

CLI и панель работают с локальным сервисом. Импорт — одна запись на строку: `почта | HTTPS-ссылка доступа к почте`. Также принимается `номер | почта | ссылка`: числовой номер, например `143`, игнорируется. Поддерживаются Luuvan, Gmail, Outlook и Generator.email; файл целиком проверяется до передачи. Адрес в ссылке должен совпадать с почтой в строке. Вставляйте только свои аккаунты и храните файл импорта в приватном месте: ссылка доступа к почте — секрет.

Для автоматического получения кода добавлены следующие формы ссылок:

```text
person@example.test | https://generator.email/person@example.test
person@example.test | https://luuvan.site/person@example.test
person@example.test | https://luuvan.site/?inbox=person%40example.test
```

Адрес `person@example.test` вымышленный — замените его своей почтой. Это альтернативные формы одной записи, а не три разных аккаунта. У Luuvan также принимаются параметры `email` и `address`; закодированный `%40` поддерживается. Если адреса в пути, параметрах и строке расходятся, импорт отклоняется.

```sh
npm run account add < accounts.txt
npm run account list
npm run account health <account-id>
npm run account login <account-id>
npm run account jobs <job-id>
npm run panel
```

В панели нажмите **«Добавить аккаунты»**: вставьте сразу несколько строк `почта | ссылка на доступ к почте` или загрузите `.txt`. За один раз поддерживается до 100 непустых строк и 64 КБ текста. Кнопка **«Проверить список»** показывает замаскированный адрес, провайдера и ошибку/дубль по каждой строке. До подтверждения ничего не добавляется. Исправьте все ошибки, затем нажмите **«Добавить аккаунты»**. Список целиком проверяется ещё раз на сервере. Точные дубли пропускаются; конфликт другой ссылки у того же адреса блокирует импорт всего пакета.

После импорта показаны количество добавленных аккаунтов, дубли и число запущенных задач входа. Прогресс задач и статусы обновляются в реальном времени. Если очередь входа заполнена, запись остаётся в списке со статусом, требующим входа: нажмите **«Войти»** позже. Есть поиск по замаскированному адресу/ID и фильтр по статусу. Исходный список не сохраняется в браузере и очищается после успешного импорта и ухода со страницы.

После импорта Luuvan и Generator.email запускают попытку автоматического получения свежего кода Muse из указанного ящика. Если получить код невозможно, формат ответа почты изменился, почта недоступна или ожидание кода истекло, задача переходит в **«Ожидает вас»**. Открываются Muse и отдельная вкладка почты в новом браузерном профиле. Введите код и завершите вход в Muse; код в панель или чат передавать не нужно. На ручной шаг даётся до 10 минут, после успешного завершения сессия сохраняется и аккаунт становится активным автоматически. Если время истекло, нажмите **«Войти»** ещё раз. CAPTCHA и принятие условий выполняет пользователь.

Berserk дожидается загрузки формы, проверяет сохранение введённого адреса и отправляет код одной попыткой: кнопкой продолжения либо Enter в проверенном поле кода. После ввода кода или ручного завершения он сам проверяет сессию Muse не чаще раза в 10 секунд. Успешный вход в интерфейсе Muse и статус **«Активен»** в Berserk — разные этапы: последний появляется после проверки и сохранения локальной сессии. После передачи управления пользователю автоматическая отправка кода прекращается; проверка уже выполненного входа продолжается.

Если Chrome открылся, но Muse не загрузился, созданное окно также остаётся для ручного продолжения. Автоматического повтора навигации нет; панель различает ошибки запуска, DNS, прокси, TLS и загрузки страницы. Защитные предупреждения не обходятся.

Сводка показывает все загруженные аккаунты, активные и нуждающиеся во внимании, очередь, уникальные запросы, успешные и ошибочные результаты, оценки входных/выходных токенов. Расход и запросы относятся **к сохранённой истории: до семи дней и до 5 000 событий**, а не ко всему сроку жизни аккаунтов. Один запрос может содержать несколько событий и попыток; общий счётчик запросов дедуплицируется по ID. Сумма расходов — приблизительная оценка текста, не биллинг Muse.

Панель запрашивает баланс через тот же read-only subscription action, который использует веб-приложение Muse. **Внутренние `topupBalance` и `topupTotal` не являются пользовательскими токенами.** В историческом наблюдении 2026-10-21 аккаунт передавал `40 000 000` внутренних единиц, а Muse показывал **`1B tokens left`**; это не измерение баланса нового аккаунта или текущего состояния. Карточка **«Дополнительные токены»** берёт количество только из подтверждённой подписи `topupRowValueLabel`; сокращённые K/M/B значения и их сумма помечаются `≈`, поскольку Muse округляет их. Внутренние числа используются только для процента расхода. Неизвестный формат подписи исключается из суммы; коэффициент пересчёта не угадывается. **Недельный лимит** показан отдельно в процентах.

Обновление запускается при старте, после смены сессии и завершения запроса; фоновый опрос раз в минуту обновляет данные старше пяти минут. Кнопки **«Обновить балансы»** и **«Баланс»** запрашивают данные вручную. Повторные нажатия объединяются, между обращениями к одному аккаунту выдерживается минимум 15 секунд; занятый аккаунт пропускается. Постоянное окно Muse для баланса не нужно.

Если часть аккаунтов не сообщила баланс, сумма помечается как частичная и показывается покрытие. Устаревшие данные после ошибки сохраняются с предупреждением и временем наблюдения; при смене ревизии сессии прежний образец сбрасывается. Дополнительные токены и недельные проценты не складываются. Расход в Berserk остаётся отдельной приблизительной оценкой.

Панель открывается сразу по **http://127.0.0.1:8787/panel** — без авторизации, одноразовых билетов, cookies и ограничения в восемь часов. Ссылку можно сохранить в закладки. Команда `npm run panel` просто открывает этот постоянный адрес. При перезапуске сервиса открытая панель переподключается автоматически.

Доступ ограничен loopback-интерфейсом этого устройства. Проверки Host/Origin и межсайтовых запросов сохранены. Для изменяющих действий интерфейс автоматически получает CSRF-маркер: это внутренняя проверка запроса, она не требует входа и не имеет срока пользовательской сессии. CLI `/control/accounts*` по-прежнему использует отдельный административный ключ из `.state/panel.key`; локальный OpenAI API — `muse-local`.

Аккаунты и сессии хранятся в `.state/accounts`, каталоги создаются с режимом `0700`, файлы — `0600`. Административный ключ CLI также имеет режим `0600`. Секреты не выводятся в журнал и не возвращаются панелью/CLI; отображается только `emailMasked`. Для автоматического входа проверяются только новые сообщения ожидаемому получателю от явно разрешённого отправителя. Luuvan читает публичный API, Generator.email — список входящих, уведомления и HTML выбранного письма. Содержимое обрабатывается в памяти; код не сохраняется в отчётах. Неизвестный формат или неподтверждённые метаданные переводят вход в ручной режим. Gmail и Outlook имеют API-адаптеры с OAuth, но обычный импорт не передаёт им OAuth-токены и использует ручной вход. Ошибка открытия вкладки почты не закрывает окно Muse: почту можно открыть по своей ссылке самостоятельно.

Health-check и re-login — явные действия оператора: после успешной проверки они могут снять карантин. Это не подтверждает завершение прежнего запроса на стороне Muse. Перед разблокировкой нужно проверить, что он завершён или остановлен; панель показывает предупреждение. Автоматическая очередь сама карантин не снимает.

Подтверждённый дополнительный баланс относится к моменту наблюдения и может измениться при использовании Muse в другом клиенте. Ошибка чтения баланса сама по себе не блокирует аккаунт и не запускает health-check или повторный вход.

## Проверки и статус

На **2026-10-25** подтверждены реальные coding-задачи Claude Code **2.1.303** и Hermes **0.16.0** через Muse на macOS: исправление кода, **3/3** теста, создание и чтение подтверждения, итоговый ответ. У Hermes совместная запись/чтение проверена отдельно; автоматический FAIL сохранён. В успешных прогонах завершились соответственно **7** и **6** запросов без ошибок. Проверен один доступный тестовый аккаунт; первые попытки имели ошибки, поэтому длительная стабильность и свежий баланс не квалифицированы. Производственный код совпал с коммитом `9375856`. Полный unit-набор 23 октября прошёл **556/556** тестов на macOS с Node 22.23.3 и 26.0.0. Подробности, прошлые отказы VM и границы проверки — в [квалификации](QUALIFICATION.md) и [руководстве по диагностике](TROUBLESHOOTING.md).

Реальная проверка публичных vendor-assets прошла на Node 22.23.3 и 26.0.0: старый lock из 213 URL имел 42 ответа HTTP 200 и 171 ответ HTTP 404; обновлённый набор из 108 файлов прошёл проверку хешей и семантических экспортов. Resolver скачал 108 файлов при обновлении, а после перезапуска повторно использовал проверенную генерацию без скачивания. Это подтверждает обновление vendor-кэша, но не live-генерацию.

**Исторические результаты 2026-10-21:** тогдашний набор прошёл 512/512 тестов на macOS с Node 22.23.3 и 26.0.0; старый манифест не описывает текущую ревизию. На Luuvan и Generator.email были подтверждены автоматический вход и сохранение сессии; у одного Generator-аккаунта также проверялись health-check, баланс и восстановление после перезапуска. Claude Code 2.1.303, Hermes 0.16.0 и OpenCode проходили прежние coding-задачи через Muse на зафиксированных тогда исходниках. Эти результаты не переносятся на текущие байты. Ранее на Debian Linux x64 прошли 416/416 тестов и запуск пустого сервиса; WSL2 не квалифицирован. Полного финального аудита Claude Opus текущей ревизии нет.

В совместимом API `usage` — локальная оценка переданного и полученного текста, а не биллинг Muse. Баланс читается отдельно из подписи Muse; абсолютный недельный остаток и контекст модели из него не выводятся.
