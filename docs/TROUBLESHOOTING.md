# Обновление и диагностика

## Обновить установленный Berserk

В папке клонированного репозитория:

```sh
npm run stop
git pull --ff-only
npm ci --ignore-scripts
npm run launch
```

Если сервис уже остановлен, первый шаг можно пропустить. Аккаунты в `.state` сохраняются. Если Git сообщает о ваших изменённых файлах, сначала сохраните их отдельно; не применяйте принудительный сброс.

## После входа запрос возвращает `needs_vendor_assets`

Muse обновляет файлы веб-клиента и удаляет прежние адреса. В старом lock-файле от 18 октября на момент проверки 23 октября **171 из 213** URL возвращал 404. Успешные unit-тесты этого не обнаруживали: они проверяли локальные fixtures.

Текущий Berserk использует обновлённый набор файлов и находит четыре необходимые функции по именам экспортов, без фиксированных номеров модулей. Перед первой генерацией и затем раз в десять минут при запросах он проверяет сборку сайта. При изменении сборки либо ответах 404/410 формирует новый ограниченный набор зависимостей, проверяет его, сохраняет хеши и атомарно выбирает кэш. Первая подготовка может занять больше времени. HTML аккаунта, cookies и почтовые ссылки в vendor-кэш не записываются.

Несовпадение хеша, неизвестный формат сборки или неполный протокол приводят к явной ошибке. Полностью произвольные будущие изменения Muse не могут гарантированно поддерживаться автоматически. Подготовка выполняется до отправки генерации; уже принятые и неоднозначные запросы не переотправляются.

Проверить доступность опубликованных файлов и разрешение экспортов без аккаунта:

```sh
npm run test:vendor
```

Эта проверка требует сети и отдельным заданием запускается в GitHub Actions. Она не доказывает работоспособность генерации или аккаунта.

## Ошибка `muse_vm_unavailable`

Вход в аккаунт и доступность сервера генерации — разные состояния. Muse может вернуть HTTP 200 с `status: unavailable` вместо назначения VM. Berserk теперь сообщает об этом прямо, сохраняет уже записанную сессию и не отправляет запрос модели. При первом добавлении аккаунта сохранение сессии по-прежнему требует назначения VM и успешного официального обмена токена; один введённый OTP не считается завершённым добавлением. Он поддерживает как прежний прямой адрес, так и новый список `vms`, выбирая назначенный предпочтительный сервер.

Откройте Muse и проверьте состояние аккаунта и сервера; при временном сбое повторите позже. Повторный вход сам по себе не гарантирует восстановления VM. Berserk не сбрасывает и не пересоздаёт сервер аккаунта автоматически. Если после кода подтверждена недоступная VM, автоматическая попытка заканчивается этой ошибкой по своему сроку, без дополнительных десяти минут ручного ожидания. CAPTCHA, условия и настоящий ручной шаг по-прежнему доступны.

## Браузерный режим зависает или отклоняет JSON

Браузер ждёт появления обработчиков ввода, доступного поля и стабильного пустого нового чата. Само наличие textarea, включая атрибут `prehydration`, готовностью не считается. После Enter он ждёт подтверждения собственного сообщения; неоднозначная отправка не повторяется.

Ответ запрашивается одним блоком JSON. Из браузера извлекается текст единственного блока кода с текущим `request_id`, чтобы Markdown не менял слеши в путях и регулярных выражениях. Проверки nonce, схем инструментов и повторяющихся JSON-ключей сохраняются. Узкое восстановление недопустимых escape-последовательностей допускается только в обычном поле `content`; аргументы инструментов остаются строгим JSON.

Явный возврат к браузерному режиму после остановки сервиса, macOS/Linux/WSL2:

```sh
MUSE_TRANSPORT=browser npm run launch
npm run login
```

Для этого режима используется отдельный браузерный профиль; вход через список аккаунтов HTTP-транспорта не заменяет вход в этот профиль.
