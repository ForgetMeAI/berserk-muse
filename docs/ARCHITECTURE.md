## Запрос, аккаунт и транспорт

```text
OpenCode → loopback HTTP API → AccountQueue → один AccountPool lease
  → Muse HTTP discovery/token calls → зашифрованный native WebSocket
  → официальный Noise client + штатная проверка attestation/notary
  → проверенный ответ → локальная сериализация и telemetry estimate
```

Генерация использует официальный Noise-клиент через WebSocket поверх TLS и сохраняет проверку trust/attestation. GET `/api/session` — отдельное HTTPS-обнаружение VM: поддерживаются прежний descriptor и новый inventory `vms`, в том числе предпочтительная VM. Отсутствие VM не считается истёкшей авторизацией и допускает переход к другому аккаунту без повторной отправки генерации.

Runtime загружает публичные chunks по manifest и ограничивает fetch известными Muse-путями. Перед первой генерацией и раз в десять минут при последующих запросах resolver сравнивает URL скриптов, включая `dpl`, с текущей страницей Muse. Авторизованный HTML используется только в памяти для извлечения публичных URL; сами JS-файлы скачиваются без credentials. При новой сборке или 404/410 обнаруживается ограниченное замыкание зависимостей четырёх именованных экспортов (`openNoiseConnection`, `NoiseChannel`, `resolveHttpRouteRequest`, `isGatewayRequestError`), включая необходимые динамические chunks. Номера модулей в прикладном транспорте не закреплены. Новый набор получает хеши, проверяется до использования и атомарно выбирается через `.state/vendor/muse-client-v1/active-lock.json`; старый подготовленный набор не переписывается. Инициализация модулей ограничена временем. Общая подготовка выполняется однократно для параллельных запросов, с отдельной отменой ожидающих; сеть владельца сохраняется до завершения очистки.

Несовпадение хеша не вызывает автоматического принятия нового содержимого. Код не отключает встроенный verifier и не подменяет его собственной проверкой. Пока текущий полный native flow и заявленные квалификационные gates не завершены, это исследуемая интеграция, а не поддерживаемый Node-клиент. Manifest — hash-lock публичных файлов, не подпись и не граница доверия; vendor code исполняется и требует повторной проверки при обновлении. Изменения неизвестного протокола могут потребовать нового исправления.

`AccountQueue` держит глобальный permit на весь логический запрос. Параметры по умолчанию: один активный логический запрос, четыре ожидающих; `MUSE_MAX_ACTIVE` ограничен диапазоном 1–8, `MUSE_QUEUE_LIMIT` — 0–100. На одной попытке используется один account lease. Fallback дожидается очистки предыдущего lease. До трёх generation-вызовов допускаются только для типизированной ошибки с доставкой `not_sent` или доказанным `rejected_before_acceptance`; `accepted` и `unknown` никогда не повторяются автоматически. Сессионное обновление само по себе не считается generation-попыткой.

Аккаунты сериализуются по email и URL почты; импорт проверяет HTTPS, отсутствие учётных данных в URL, домен из allowlist и предел 1 MiB/100 строк. `parseImportLine` принимает две колонки или числовой префикс и три колонки; `extractImportEmail` нужен для безопасного маскирования ошибок предпросмотра. `mailAccessUrl` хранится отдельно от публичной записи. Локальные account/session каталоги имеют режим `0700`, файлы — `0600`; хранение атомарное и защищено от symlink/hardlink-подмены. При входе OTP ищется только после подтверждённого Muse-запроса, в свежем сообщении для точного получателя и разрешённого отправителя; текст и ссылки не исполняются. Gmail/Outlook требуют OAuth; обычный login-путь его не передаёт и переходит к ручному входу. Generator.email использует отдельный автоматический адаптер с проверкой адреса в пути и ручным fallback. Relogin — временный интерактивный браузерный процесс; секреты сессии не журналируются.

При недоступном автоматическом чтении, ошибке или таймауте OTP bootstrapper однократно переходит в ручной режим, открывает проверенный mail URL во второй вкладке того же нового context и возвращает Muse на передний план. Чтение HTML/OTP этой вкладки сервером не выполняется. Однократный ручной deadline — до 600 секунд; он не продлевается каждым poll. Token exchange ограничен оставшимся временем и максимум 30 секундами, включая внешний Node watchdog и in-page fetch timeout. Закрытие/отмена завершает только принадлежащий задаче context. `setPhase` передаёт только allowlisted enum: `opening_browser`, `requesting_code`, `reading_mail`, `waiting_for_user`, `saving_session`; JobManager, service и router повторно ограничивают публичную проекцию. Терминальные задачи фазу очищают. Панель показывает ручную инструкцию во время ожидания; статус active публикуется после сохранения полученной сессии, не после импорта или предпросмотра.

## Панель и локальные маршруты

Shell выдаёт только внешние статические файлы `/panel`, `/panel/app.js`, `/panel/model.js` и `/panel/style.css`; CSP запрещает inline script/style. `model.js` содержит чистые расчёты публичных оценок/остатков без транспорта и секретов. Панель доступна по постоянному loopback URL без авторизации, билетов, cookie и TTL. Bootstrap возвращает snapshot и CSRF nonce текущего router; nonce используется автоматически, не является пользовательской сессией и обновляется после перезапуска. Изменяющие запросы требуют точный Origin и CSRF header; Host ограничен localhost/127.0.0.1 с портом сервиса, сторонние Origin/межсайтовые API-запросы отклоняются. SSE не зависит от сессии и работает до закрытия клиента/сервера. `/control/accounts*` сохраняют проверку отдельного admin bearer. Старые маршруты выдачи билета, обмена сессии и logout больше не используются и не дают доступ.


| Маршрут | Назначение |
| --- | --- |
| `GET /panel/api/bootstrap` | CSRF token и текущий snapshot |
| `GET /panel/api/accounts` | только allowlist полей аккаунтов, `emailMasked` |
| `POST /panel/api/usage/refresh` | обновление балансов; 202 `{queued,skipped,pending}` (Origin + CSRF) |
| `POST /panel/api/accounts/:id/usage-refresh` | обновление баланса одного аккаунта; тот же формат (Origin + CSRF) |
| `POST /panel/api/accounts/preview` | `{accounts:string}` до 64 КБ / 100 строк; проверка без мутаций, замаскированные построчные результаты (Origin + CSRF) |
| `POST /panel/api/accounts/import` | повторная проверка и атомарное добавление через существующий сервис; счётчики и публичные задачи входа (Origin + CSRF) |

| `GET /control/accounts` | CLI/admin список с маскированной почтой |
| `POST /control/accounts` или `/control/accounts/import` | импорт партии через CLI/admin bearer |
| `POST /control/accounts/:id/relogin` или `/health-check` | CLI/admin создать задачу |
| `GET /control/jobs/:id` | CLI/admin получить состояние задачи |

Панель сериализует только allowlist публичных полей. Ошибки заменяются безопасным кодом и фиксированным текстом. `estimatedUsage` остаётся оценкой; `upstreamQuota` показывается только если источник передал whitelisted numeric fields и единицу измерения. Остаток квоты не выводится из локальной оценки. SSE имеет ограниченную очередь и отключает медленных клиентов; события не несут приватные account/session/mail данные.

## Баланс Muse

`createMuseProtocol().readUsage(account,session,{signal})` выполняет только `POST https://muse.ai/`, Next Action `4029ac5c4bd03136487d91ebde5de39c64b35229b4` (`fetchSubscriptionAction`), с телом `[{"includeAgreement":false}]`. Используются сохранённые cookies и обычные fingerprint-заголовки; ответ — React Flight `text/x-component`. Метод не поднимает VM/Noise, не запускает генерацию и не вызывает purchase/referral actions. ID привязан к исследованной версии веб-приложения и может измениться. HTTP 401/419/403 и форматные ошибки дают фиксированные коды; ответ и секреты не попадают в журнал. Ротация cookies сохраняется compare-and-swap с текущей ревизией сессии.

Ограниченный JSON-only parser (1 MiB, до 256 строк) извлекает `tier`, `usage.percentUsed/state/resetsAt/quotaStatus`, `topupBalance`, `topupTotal` и `topupRowValueLabel`. Важно: внутренние topup-числа имеют единицу `muse_quota_units`, а не пользовательские токены. На проверенном аккаунте raw 40M соответствует серверной подписи `1B tokens left`; универсальный коэффициент не выводится из одного примера. Строгий parser извлекает пользовательский остаток только из этой подписи, compact K/M/B помечает как приблизительный; неизвестный формат даёт null, без выдуманного пересчёта. Противоречивые raw значения отвергаются.

Канонический образец: `source:'muse_subscription'`, `observedAt` в миллисекундах, `tier:{code,name,isPaid}`, `weekly:{state,percentUsed,resetsAt,quotaStatus}`, `additional:{remaining,limit:null,used:null,percentUsed,approximate,displayLabel,raw:{remaining,limit,unit:'muse_quota_units'}}`. Процент считается только по raw отношению, остаток в токенах — только из provider label. Кэш и router повторно канонизируют его, не доверяя отдельно переданному числу. `resetsAt` сохраняется в исходной единице и пока не выводится как дата. Agreement, платёжные данные и тексты upstream-ошибок не проецируются. Абсолютная недельная квота не выводится из процента.

`AccountUsageService` использует account-exclusive lock общего пула, максимум два чтения и 200 ожидающих; занятые аккаунты пропускаются. Инициализация, смена store, завершение запроса и ручные действия объединяются; polling 60 с, TTL 300 с, cooldown 15 с. SSE/list/bootstrap читают только кэш, не инициируют сетевой вызов. При ошибке последний образец остаётся `stale`; при смене ревизии сбрасывается, недоступная/заблокированная сессия не считается свежей. Закрытие отменяет и дожидается текущих операций до закрытия store/pool. Баланс не изменяет статус/карантин аккаунта.

Публичный `museUsage` содержит `state,pending,observedAt,attemptedAt,errorCode,sample`; `sessionRevision` наружу не отдаётся. `upstreamQuota` совместимости заполняется только из проверенного `additional.remaining` с `unit:'tokens'`; raw туда не попадает. Общая сумма округлённых подписей помечается `≈`; недельные проценты не суммируются. Неполное покрытие, старые данные и обновление явно помечаются. Кэш живёт в памяти, после перезапуска загружается заново.

## Клиенты и платформы

`src/anthropic.mjs` переводит Messages в существующий внутренний контракт и обратно; `src/server.mjs` использует ту же очередь, telemetry и Muse transport. `/v1/messages/count_tokens` только валидирует/оценивает текст до создания generation request. Anthropic SSE использует именованные события и `message_stop`, без OpenAI `[DONE]`. Text-only tools поддерживаются, reasoning/constraints не имитируются и помечаются как unsupported. Для предварительной проверки Claude Code допускается пустой `HEAD /` после Host/Origin, без доступа к данным или генерации. Hermes optional tool-result `name` принимается только при совпадении с именем связанного вызова.

`src/agent-clients.mjs` и `scripts/client.mjs` создают отдельные профили и allowlisted env. Claude temp/config и Hermes home привязаны к новому профилю. Для распознанного source checkout Hermes наличие fallback `PROJECT_ROOT/.env` блокирует запуск до создания профиля; проверяются только метаданные. Произвольные wrapper-скрипты этой проверкой не квалифицированы. Это обычный интерактивный запуск с разрешениями самого клиента, а не обещание OS sandbox. Hardened verification имеет отдельный macOS profile и не переносится на Linux/WSL автоматически.

Claude process env содержит `CLAUDE_CODE_MAX_RETRIES=0`. Hermes custom Chat Completions получает `agent.api_max_retries:1` (одна внешняя попытка) и `HERMES_STREAM_RETRIES=0`; в исследованной 0.16.0 per-request OpenAI client уже создаётся с `max_retries=0`. Эти настройки не меняют глобальные клиентские профили. `TMPDIR`, Claude temp и zsh `TMPPREFIX` направлены внутрь отдельного профиля. Manual live runners требуют явный путь к клиенту, не запускаются при импорте и сохраняют отрицательные результаты. Claude ограничен Bash, Hermes — terminal. У Hermes loopback relay запрещает повтор тела запроса и прекращает пересылку при отказе инструмента, ошибке API или неоднозначной доставке. Временное auto-approval Hermes включается только в дочернем процессе явно разрешённого изолированного теста.

Полный успех требует фактических RED/read/edit/GREEN/proof-create/proof-read, неизменяемого теста, финального результата и отдельного verifier без сети. Ledger автоматически засчитывает отдельный проверенный proof-read; совместная запись/чтение даёт лишь `proofReadRequiresOfflineReview`, поскольку поиск названий JS-вызовов не доказывает выполнение чтения или происхождение stdout. Реальный Hermes-прогон от 2026-10-19 квалифицирован отдельным офлайн-отчётом с точным совпадением хешей команды/результата и независимым подтверждением чтения с диска. Исходный автоматический FAIL сохранён без изменений.

`src/platform.mjs` реализует Linux browser discovery, явный `MUSE_BROWSER_EXECUTABLE`, `open`/`xdg-open` и корректные file URLs. Native win32 явно отказывается до открытия state; Windows предназначен для запуска через WSL2/Linux filesystem. На Debian Linux x64/Node 22.23.3 проверены 416 тестов и жизненный цикл пустого сервиса с панелью, без браузера/входа/генерации Muse. Linux-прогон привязан к переданному архиву; последующее уточнение двух macOS-only verification-файлов имеет отдельные локальные тесты и манифест. Реальная WSL2-система ещё не проверялась. POSIX-проверки 0600/0700 и Chromium sandbox не ослаблены. CI Ubuntu/macOS Node 22/26 содержит unit tests и launch/status/stop; актуальные результаты опубликованных коммитов доступны в GitHub Actions репозитория.

## Почтовые адаптеры

Luuvan использует только фиксированный API HTTPS-хоста `luuvan.site`: `/api/public/inbox?address=…` и `/api/public/messages/{id}?address=…`. Общий `mailboxFromUrl` принимает `/email`, `?inbox=email`, `?email=email` и `?address=email`, отклоняя конфликты с ожидаемым адресом. Получатель берётся из явных полей ответа либо объявленной сервером привязки ящика; URL сам по себе не подменяет отсутствующие метаданные письма.

Generator.email имеет отдельный адаптер HTML/WSS с фиксированными HTTPS-хостами `generator.email`/`www.generator.email`. Импорт принимает `/email`; публичный JS сайта описывает уведомления `/notificon/ws?email=…` с полями `link`, `from`, `subject`, `date`, список `#email-table` и слоты `#mail-summary-head`/`#mail-summary-body`. Адаптер не исполняет скрипты и не обходит антибот-проверки. Ограничения размера, адресата, свежести и переходов действуют до передачи кода в Muse. Неизвестная схема приводит к ручному fallback. Синтетические тесты подтверждают контракт адаптера; полный вход через реальный ящик требует отдельной live-проверки.

В некоторых письмах Generator не показывает адрес в шапке. Тогда нормализованное поле `to` обозначает подтверждённый ящик доставки, а `recipientSource: 'mailbox_context'` явно отличает его от заголовка письма. Подтверждение берётся только из единственного серверного `inbox_ctx` в финальном HTTPS-ответе: ящик и точный ID сообщения должны совпасть с проверенной ссылкой из списка. Исходящий cookie, адрес в URL или в остальных частях HTML доказательством не считаются. Явный чужой, некорректный или неоднозначный получатель отклоняется и при совпавшем контексте. `Reply-To` не считается полем `To`.

Gmail использует Google Mail API, Outlook — Microsoft Graph. Для Google/Microsoft необходим OAuth-токен с соответствующим mail-read разрешением; обычный импорт не передаёт его и использует ручной вход. Почтовые URL и OAuth токены секретны: не помещаются в публичный API, CLI output, телеметрию или журналы. Bootstrapper начинает чтение только после успешного запроса Muse send-otp для ожидаемого адреса; отмена и переход в ручной режим прекращают автоматическую отправку кода. CAPTCHA и принятие условий остаются ручными шагами.

Ошибки запуска браузера и навигации имеют отдельные фиксированные коды. `onDiagnostic(event)` передаёт проверенную схему: `launch` содержит `reason`; `navigation` дополнительно содержит только фиксированные `pageState`, `errorType` и слова из закрытого списка `signals`. Исходные исключения, URL, адреса аккаунтов и произвольный текст в журнал не попадают. Список 249 допустимых Chromium `ERR_*` сохранён в `src/accounts/chromium-net-errors.json`; источник — официальный [net_error_list.h](https://chromium.googlesource.com/chromium/src/+/main/net/base/net_error_list.h), извлечение 2026-10-20, SHA-256 исходного файла `8647b49488fbd0856ff03056c459ddfd115a89533637ddb8037637e9c7def243`. Неизвестные коды сводятся к `unknown`.

Для точного POST `/api/auth/native/send-otp` с совпавшим получателем диагностика `otp_response` содержит только `httpStatus`, фиксированные `bodyKind`/`statusFlag`, булевы `successFlag` (либо `null`) и `hasError`. Диагностика охватывает и non-2xx, но чтение почты начинается только после 2xx. Неверный или превышающий 1 МиБ `Content-Length` запрещает чтение. При отсутствии длины допускается ограниченное ожидание `response.body()`: возвращённый Buffer проверяется на размер до JSON.parse. Проверка ограничивает обработку, но не внутреннее буферизование самим Playwright. Все чтения ограничены пятью секундами и оставшимся сроком входа, учитывают отмену. Содержимое и коды не сохраняются. Диагностика асинхронна, не задерживает поллинг и подавляется после отмены, закрытия страницы или финализации контекста. HTTP 2xx сам по себе не считается доказательством доставки письма или завершённого входа.

`email_submit` содержит только фиксированный `outcome`, категорию `buttonCount`, булевы либо `null` `buttonVisible`/`buttonEnabled`/`emailMatches`. Последнее поле сравнивает итоговое значение поля с ожидаемым адресом в памяти, не передавая само значение в журнал. Начальная навигация ожидает `load`; адрес вводится клавиатурными событиями (`pressSequentially`, 20 мс между символами), если API доступно, иначе используется прежний `fill`. Перед нажатием кнопки значение повторно сравнивается с ожидаемым адресом; сброс или неподтверждённое значение дают `email_not_retained` и ручной вход. Это ограничивает нестабильный ранний ввод, но не доказывает конкретную причину сброса в Muse.

Одна попытка ввода допускает одно нажатие кнопки с ожиданием её готовности не более 5 секунд; неудача сразу переводит вход в ручной режим. Повторных отправок кода эта диагностика не запускает. Нажатие кнопки не заменяет проверку HTTP-ответа и входа.

Поле OTP ищется также по вычисленному accessible name Playwright, включая `aria-labelledby`. Видимая надпись «Войти» не переводит форму в ручной режим, пока доступен такой узкий locator кода. `verification` сообщает только фиксированный итог получения кода, `otp_submit` — фиксированный исход попытки ввода/отправки; сам код, письмо и надписи из интерфейса в callback не передаются.

Код OTP также набирается клавиатурными событиями, если доступен `pressSequentially`; после предварительной очистки повторно проверяется отмена и ручной режим. Для отправки выбирается одно действие: единственная видимая кнопка продолжения либо Enter в единственном всё ещё видимом, доступном поле с ожидаемым значением. Перед Enter повторяются проверки origin и отмены; после ручного переключения он запрещён. Исчезновение, отключение или изменение значения поля дают различные фиксированные диагностические исходы, без самого значения, и не вызывают повторной отправки.

Помимо пассивных ответов страницы, после заполнения OTP или ручного переключения bootstrapper делает GET `/api/session` из своего Muse-контекста: первая попытка сразу, затем не чаще раза в 10 секунд. Запрос использует браузерные cookies и ограничен `AbortSignal.timeout` и внешним watchdog до 10 секунд, с учётом оставшегося срока. Ответ потребляется в браузере и не возвращает в helper JSON или credentials; существующий response handler отдельно проверяет сессию. Неудача или 401 не повторяют OTP и не продлевают срок. Проба запрещена вне Muse-origin, после отмены и после дедлайна.

`vm_name` в ответе сессии необязателен, как в HTTP-транспорте: отсутствующее, `null` или пустое значение исключается из upstream, token-аргументов и сохраняемого объекта. `endpoint_url` и `vm_id` остаются обязательными. Login распознаёт также `wss:` endpoint, используемый основным транспортом; ранее этот вариант ошибочно отбрасывался. Ключ со значением `undefined` не сохраняется, поскольку хранилище принимает только обычный JSON. Wake-запрос не добавлен в login: существующий refresh-контракт допускает token exchange без него.

Health-check воспроизводит bodyless POST `/api/auth/check` без `Content-Type`. Успех — HTTP 200 с `outcome: "validated"`, как в публичном клиенте Muse; app-level `access_token` необязателен и в native transport не используется. Он не заменяет gateway credential: дальше выполняются GET `/api/session` и отдельный POST `/api/hatch/token`. Каждый запрос проверки ограничен 15 секундами либо меньшим настроенным timeout. Только точная трёхполевая схема `{type: "hatchAdmissionInvalidated", reason: "session", status: 401}` при HTTP 401 даёт явный verdict повторного входа на auth-check. Неизвестные 401/419/403, checkpoint/activation/entitlement и неожиданный HTTP 200 дают временную ошибку проверки без смены статуса аккаунта. На следующих этапах refresh сохраняется существующая обработка истёкшей сессии. Публичный ответ `{ok: true}` больше не считается контрактом Muse.

Для Muse API задаются стандартные Fetch Metadata браузерного same-origin запроса: `Sec-Fetch-Site: same-origin`, `Sec-Fetch-Mode: cors`, `Sec-Fetch-Dest: empty`, вместе с Muse Origin/Referer. Они описывают текущий API-запрос и заменяют отсутствующие или устаревшие navigation-значения сохранённого fingerprint. Cookies и проверка TLS обязательны; повторов или обхода HTTP 403 нет. В живой диагностике отсутствие этих метаданных давало 403 на auth-check, а корректный запрос — 200.

Диагностика `session_response` содержит только `httpStatus` и булевы `bodyParsed`, `endpointPresent`, `vmIdPresent`, `vmNamePresent`, `accepted`. Она относится только к точному GET Muse `/api/session`; non-200 тела не разбираются. Сохраняется не более трёх различных форм диагностики за вход, с местом для последующего успешного ответа. Ни upstream-адрес, ни VM ID/имя, ни cookies, headers или tokens в callback не попадают.

Разбор тела ответа сессии также ограничен оставшимся сроком входа и максимум 10 секундами; получение необязательных fingerprint-заголовков — оставшимся временем и максимум одной секундой. После отмены или финализации новые response-события не запускают ни чтение почты, ни разбор сессии. Поздно разрешившийся Promise не меняет результат уже завершённой задачи.

Если навигация завершилась ошибкой, но созданная вкладка жива, она сохраняется для ручного завершения в пределах того же 10-минутного срока; повторной автоматической навигации нет. Закрытая вкладка и отмена завершают задачу сразу. При истечении ручного срока сохраняется первоначальная сетевая причина. Ошибка могла оставить пустую вкладку: сохранённое окно само по себе не подтверждает загрузку Muse или готовность формы входа.

## Жизненный цикл native WebSocket

`src/net/websocket-process.mjs` запускает штатный Node WebSocket в собственном процессе из `websocket-worker.mjs`. URL авторизации и бинарные кадры передаются только по локальному IPC, без argv, журналов и сохранения. IPC ограничен 8 MiB и 1024 ожидающими сообщениями; выход родителя завершает worker. После короткой попытки штатного close родитель завершает только свой дочерний процесс. Состояние CLOSED публикуется после его фактического выхода, когда сокеты ОС уже освобождены. Это не означает завершения ранее принятой удалённой генерации: неподтверждённая отмена по-прежнему требует карантина. Ошибка установки Noise до вызова генерации допускает существующий единственный refresh/reconnect; принятый или неоднозначный запрос не переотправляется очередью.
