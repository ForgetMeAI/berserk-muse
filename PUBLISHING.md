# Публикация и сопровождение

Этот документ описывает выпуск Berserk в GitHub. Он не предполагает конкретного владельца или адрес репозитория; сопровождающий использует подтверждённый адрес проекта.

## Перед выпуском

1. Сверьте версию в `package.json`, `package-lock.json` и записи выпуска.
2. Проверьте изменения и состав отправляемых файлов. Не включайте `.state/`, `workspace/`, `.verification/`, `node_modules/`, временные результаты, локальные отчёты, учётные данные или данные реальных аккаунтов.
3. Убедитесь, что README, лицензия, `NOTICE` и инструкции безопасности соответствуют текущему выпуску. Для сторонних материалов сохраняйте требуемые уведомления.
4. Установите зависимости и выполните `npm test`. Учитывайте ограничения и условия запуска интеграционных проверок из README.
5. Проверьте результат workflow GitHub Actions для выбранного коммита.

## Отправка в GitHub

1. Выберите существующий репозиторий или создайте новый в подтверждённой организации или учётной записи; проверьте его точный адрес и требуемую видимость.
2. Перед коммитом просмотрите staged-файлы и убедитесь, что в набор не попали локальные данные или артефакты.
3. Настройте remote на подтверждённый адрес и отправьте согласованную ветку.
4. Проверьте результат отправки и CI. Для релиза создайте тег и заметки выпуска только если это требуется проекту.

Вход в GitHub выполняйте штатным локальным способом. Не помещайте пароли, токены или другие секреты в документы, команды, исходники или сообщения.

## Пакет npm

`package.json` содержит `private: true`, чтобы предотвратить случайную публикацию пакета в npm. Публикация исходников в GitHub от этого не зависит. Изменяйте этот флаг и выпускайте npm-пакет только отдельным решением сопровождающих после проверки состава и готовности пакета.
